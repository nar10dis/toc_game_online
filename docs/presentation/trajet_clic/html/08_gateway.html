GATEWAYÉTAPE 4 · RÉCEPTION

La gateway reçoit le message

Côté NestJS, game.gateway.ts est la porte d'entrée du WebSocket.
backend/src/game/game.gateway.ts
69// La valeur retournee part dans l'ack du client : { ok } ou { error }.
70// Le nouvel etat, lui, arrive a tout le monde via commit -> broadcast.
71@SubscribeMessage('action')1
72handleAction(@ConnectedSocket() client: Socket, @MessageBody() body: { gameId: number; action: GameAction }) {
73 try {
74 this.gameService.playAction(body.gameId, client.data.userId, body.action);2
75 return { ok: true };3
76 }
77 catch (error) {
78 return { error: (error as Error).message };4
79 }
80}
1
@SubscribeMessage('action') : l'équivalent d'une route HTTP, mais pour un message.
2
Le userId vient de client.data (vérifié à la connexion), jamais du message.
3
Ce qu'on return part dans l'ack du client.
4
Une exception du service devient { error }, par exemple « Not your turn ».
La gateway ne connaît aucune règle. Elle identifie le client, transmet l'action au service et traduit le résultat en réponse.
